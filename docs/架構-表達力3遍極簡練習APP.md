# 架構規劃：表達力 3 遍極簡練習 APP

> 日期：2026-08-27 ｜ 狀態：待確認 ｜ 來源需求：docs/需求-表達力3遍極簡練習APP.md
> ⚠️ 開工前先讀 CLAUDE.md 的「最高原則」

## 1. 使用形式

- 單人自用，不需帳號、不需協作
- 手機（Android Chrome）為主要裝置
- 做成可安裝的網頁 APP：從瀏覽器選「加到主畫面」後，桌面出現圖示，點開全螢幕執行
- 放在 GitHub Pages，網址固定
- 除了 AI 檢查那一步之外，全程可離線使用

### 使用者從頭到尾怎麼走

1. 點桌面圖示 → 直接進入今日練習畫面，不需輸入任何文字
2. 按「開始第 1 遍」→ 講 → 按停止
3. 畫面顯示這一遍的逐字稿、秒數、字數、贅詞數
4. 第 2 遍、第 3 遍同上，並額外顯示與前一遍的差距
5. 中途可以離開。下次打開回到未完成的那一遍繼續
6. 三遍講完 → 補上主題標題
7. 按「AI 檢查」→ 顯示四項分析
8. 存檔完成。逐字稿、數據、AI 分析永久保存；音檔 7 天後自動清除
9. 需要時進歷史紀錄，用關鍵字搜尋（範圍：標題＋逐字稿）

## 2. 系統拆分

| 模組 | 負責 | 不負責 | 對外接誰 |
| --- | --- | --- | --- |
| 錄音模組 | 開始／停止錄音、正數計時、產生音檔 | 轉文字、存檔 | 瀏覽器錄音功能 |
| 辨識模組 | 即時轉文字、斷網偵測與標記 | 錄音、修錯字、算數據 | 瀏覽器語音辨識 |
| 數據模組 | 算秒數、字數、語速、贅詞數、贅詞密度、與前一遍差距 | 判斷內容好壞 | 無 |
| 儲存模組 | 本機資料庫讀寫、7 天清音檔、釘選、匯出 | 畫面、資料正確性 | IndexedDB |
| AI 模組 | 組提示詞、呼叫 Gemini、解析、錯誤處理 | 算數據、決定何時呼叫 | Gemini API |
| 畫面模組 | 三遍流程引導、逐字稿呈現、歷史、搜尋、設定 | 任何運算與存取邏輯 | 以上五個模組 |

## 3. 資料與外部串接

### 存哪些資料

**一次練習**：唯一編號、日期、主題（三遍後補）、狀態（未完成／已完成）、三遍的資料、AI 分析結果、是否釘選

**一遍**：第幾遍、錄音檔、秒數、逐字稿、是否為斷網未補字、字數、語速、贅詞數、贅詞密度

**設定**：Gemini 金鑰（只存本機，不進原始碼、不上傳）

### 串接哪些外部服務

只有一個：Gemini API，用於 AI 檢查。其餘全部在瀏覽器內完成。

### 贅詞預設清單

使用者三遍練習中實際出現的：然後、就是、那麼、呢、我覺得

一般常見的：這個、那個、其實、基本上、老實說、對啊、嗯、啊、之類的、什麼的、的話、我跟你講、你知道嗎

第一版不提供自訂。七天試用後若發現個人慣用詞再補。

## 3.4 設計方向

### 色票

| 用途 | 色碼 | 說明 |
| --- | --- | --- |
| 背景 | `#FAF6F0` | 米白，像練習簿紙張，夜間不刺眼 |
| 卡片底 | `#FFFFFF` | 純白，浮在米白背景上形成層次 |
| 主色 | `#8B6F52` | 奶茶棕，用於主要按鈕與標題 |
| 輔色 | `#D9C7B4` | 淺卡其，用於分隔線、次要邊框 |
| 強調色 | `#C1654F` | 磚紅，只用在錄音中狀態與需要注意的數字 |
| 文字主 | `#3D3630` | 深褐，比純黑柔和，長時間看不累 |
| 文字次 | `#8A7F73` | 灰褐，用於秒數、日期等輔助資訊 |
| 進步 | `#5F7A52` | 苔綠，數據比前一遍變好時 |
| 退步 | `#B08968` | 淺褐，數據比前一遍變差時。刻意不用紅色，避免變成責備 |

### 字體方向

- 標題：中文黑體，字重中等偏粗，不要過細。手機上要一眼看清
- 內文與逐字稿：中文黑體常規字重，行高放寬到 1.8，讓大段辨識稿好讀
- 數字：等寬字體。秒數、字數在三遍之間要能上下對齊比較
- 全部使用系統內建字體，不載入外部字型檔，確保離線可用

### 版面原則

- 首屏只放一件事：今天的練習，以及一顆大的錄音按鈕
- 錄音按鈕置於畫面下方三分之一處，單手拇指可及
- 逐字稿用卡片承載，圓角 12px，白底浮在米白背景上
- 數據放在逐字稿卡片下緣，小字灰褐，不搶注意力
- 歷史紀錄、設定收在右上角，不佔主畫面
- 三遍的逐字稿比對採上下堆疊，不用左右並排。手機寬度不夠橫排

### 設計理由

- **選米白不選純白**：這個 APP 主要在晚上使用，純白背景在暗處會刺眼，用久了會不想打開。能不能撐過七天，順手度是唯一驗收標準。
- **退步用淺褐不用紅色**：這是自我練習工具，沒有別人在看。紅色會讓人把「今天講長了」讀成失敗，降低隔天打開的意願。
- **不放進度條、不放連續天數**：任何累積型的視覺元素都會製造「不能斷」的壓力，斷一天之後就再也不想開。
- **錄音按鈕做大且放低**：使用場景是通勤途中、收工後，多半單手操作。按鈕小或放高，每天都會多一次不順。

## 3.5 技術選型

| 項目 | 選用 | 為什麼（白話） | 費用 |
| --- | --- | --- | --- |
| 語言 | HTML + CSS + 原生 JavaScript | 畫面只有三四個，用不到框架的好處。改一個檔案就是改一件事，AI 接手最直接 | 0 |
| 框架 | 不使用 | 同上 | 0 |
| 資料存哪 | IndexedDB（瀏覽器本機資料庫） | 要存錄音檔，其他本機儲存方式容量不夠 | 0 |
| 主機部署 | GitHub Pages | 已有帳號，網址固定好記，改版覆蓋即可，手機圖示不用重裝 | 0 |
| 外部服務 | Gemini API | 只有 AI 檢查需要連外 | 免費額度內 |
| AI 模型 | Gemini 2.5 Flash | 三段一千餘字的中文比對，這種用途不需要更貴的。比較過 Gemini 2.5 Pro（每月約 10 元）與 Claude／GPT（每月約 15～30 元，且需綁卡），品質差異在此用途上不明顯 | 免費額度內 |
| 語音轉文字 | 瀏覽器內建 Web Speech API（zh-TW） | 免費且即時。比較過雲端轉寫服務（每分鐘約 0.2 元），準確度略高但要等、要設定、要付費 | 0 |
| 知識怎麼存 | 整包送 | 每次只送三遍逐字稿共約一千餘字，資料量小，全部送最準，不需要挑段落 | 併入 AI 費用 |
| 測試工具 | Vitest | 後續全靠 AI 改程式，沒有自動檢查就無從判斷有沒有改壞別的地方 | 0 |

以上全部由使用者拍板確認。

**整體交代**

- **多少錢**：0 元。唯一可能付費的是 AI 檢查超出免費額度，一天一次不會超過
- **好不好維護**：全部是檔案，沒有伺服器、沒有帳單、沒有會突然停掉的服務
- **換人接手難不難**：純網頁加上 CLAUDE.md 最高原則，任何 AI 打開就能接手

    歷史紀錄的詳細頁根本沒有分析按鈕，錯過就補不回來
  - 測試先行：已有分析結果時仍看得到「重新分析」；
    歷史紀錄詳細頁沒有分析結果時出現「做 AI 分析」，按下去會存回同一筆；
    重跑後新的分析覆蓋舊的，逐字稿與數據不受影響
  - 相依：T19（一起改文字，不要改兩次）

- [ ] **T21 可以重錄，中斷了也接得回來**
  - 來源：使用者 2026-08-27 提出。實際情況有三種——
    （一）錄到一半卡住
    （二）臨時有事必須中斷
    （三）講得不滿意想重來
  - 現況問題：一遍一旦停止就定案，沒有任何重錄入口；
    練習進行到一半也沒辦法整次作廢重來（只能事後從歷史紀錄刪掉）
  - 要做的：
    - 錄音中提供「取消這一遍」：不留下紀錄，直接回到「開始第 N 遍」
    - 已完成的某一遍提供「重錄第 N 遍」：蓋掉那一遍的逐字稿與數據，
      其他遍不動（差距會自動重算，因為差距是即時從數據算出來的）
    - 今日練習提供「整次重來」：把這一次練習作廢，重新開始三遍
  - **需要先確認**：「暫時中斷」是指哪一種？
    （甲）暫停後繼續，秒數與逐字稿都接續下去
    （乙）放棄這一遍，等一下重錄
    兩種做法差很多，動工前要先問使用者。甲會讓「一遍幾秒」的定義變複雜
    （暫停的時間算不算？），乙則單純很多
  - 測試先行：錄音中按取消 → 沒有新增任何一遍，回到原本的第 N 遍；
    重錄第 2 遍 → 第 2 遍換成新內容，第 1、3 遍不變，第 3 遍的差距跟著重算；
    整次重來 → 舊的那筆不留在歷史紀錄裡，回到第 1 遍待開始
  - 相依：T19（文字一起改）
  - 附帶追查：「錄到一半卡住」的實際症狀要問清楚——
    是計時器停住，還是逐字稿不再更新。後者可能已經被
    「onend 自動重啟」那次修掉了，需要實機確認
